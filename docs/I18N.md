# Languages

TermiPaw is available in English, 简体中文, 繁體中文, 日本語, 한국어, Français, Español and Deutsch. It follows the Windows display language by default; the language can be changed in Settings and takes effect immediately. Languages that are not supported fall back to English.

English and Simplified Chinese are written by the maintainer. The other six languages were translated with AI assistance and **have not been reviewed by native speakers**. Corrections are very welcome.

## Correcting a translation

1. Find the text in `src/i18n/<language>.ts`. Every text has a name such as `vault.unlock`, grouped by area of the interface; `en.ts` is the reference.
2. Check [GLOSSARY.md](../src/i18n/GLOSSARY.md) for the fixed translation of terms such as *vault*, *master password*, *recovery key* or *host fingerprint*. If a term itself is wrong, change it in the glossary and everywhere it is used.
3. Open a pull request, or an issue quoting the current text and your suggestion.

Guidelines:

- Keep security warnings direct (host key changed, overwriting files, resetting the vault). Do not soften them.
- Keep technical names untranslated: SSH, SFTP, SSH Agent, SHA256, `known_hosts`, `user@host:port`, and keyboard shortcuts.
- Texts with parameters are functions. Word order and plural forms can be adjusted freely; the parameters must stay.
- Texts marked with `<b>…</b>` keep the tags around the same idea.

## Adding a language

1. Copy `en.ts` to a new file and translate it. The file's type is `Messages`, derived from `en.ts`, so a missing entry, an extra entry or a wrong parameter is a compile error.
2. Register it in `src/i18n/index.ts` (`LANGUAGES` and `catalogs`) and in the detection rules in `src/i18n/detect.ts`.
3. Add the backend texts in `src-tauri/src/i18n.rs`: the titles of system file dialogs, the confirmation word for resetting the vault, and the startup error shown when the data folder is not writable.
4. Add a column to the glossary.
5. Run `npm run test:unit` and the multi-language end-to-end suite.

## How it works

- **Choosing the language:** the first supported language in `navigator.languages` (which follows the Windows display language). `zh-TW`, `zh-HK`, `zh-MO` and `zh-Hant*` use Traditional Chinese; other `zh*` use Simplified Chinese.
- **Using texts in components:** `const m = msg()`, then `m.vault.unlock`. A misspelled name is a TypeScript error. Changing the language re-renders the whole interface.
- **Backend texts:** the Rust backend never builds sentences. It returns a code and parameters (for example `ssh.stepTimeout` with `what` and `seconds`), and the interface translates them. Server responses and library error messages are passed through untranslated as a `detail` parameter. A unit test checks that every code used in the Rust code has a translation and that no translation is unused.
- **Texts shown by the backend itself:** system file dialog titles, and the confirmation word for resetting the vault, which the backend checks so that the interface cannot skip it. The interface tells the backend the current language at startup and whenever it changes.
- **Formatting:** numbers and sizes use `Intl.NumberFormat` with the current language passed explicitly. `<html lang>` follows the language so that Chinese, Japanese and Korean characters use the right font: Microsoft YaHei UI, Microsoft JhengHei UI, Yu Gothic UI and Malgun Gothic.

## Not translated

- Terminal output, file names, and errors returned by servers.
- The shell integration snippet users add to `~/.bashrc` or `~/.zshrc`. It is plain ASCII English, because the server's encoding may not be UTF-8.
- Release notes, which come from a single `latest.json` and are written in English (with a Chinese section).

## Tests

- **Unit tests:** every language has the same entries and parameters as English; bold markers are paired; backend codes and translations match; the reset words match between the interface and the backend; language detection; no hard-coded Chinese, Japanese or Korean text outside `src/i18n/`.
- **End-to-end tests, for each language:** the welcome page, settings, host editor, command palette, host key prompt, password prompt (with a deliberate wrong password to show a backend error), file panel, context menus and system file dialogs. They check that nothing is left untranslated, no text names are shown, and no text is cut off or overflows. Switching languages takes effect immediately and persists after a restart. The French reset word actually resets the vault and other languages' words do not.

## Known limitations

- System dialogs (for example the buttons of file dialogs) follow the Windows language, not TermiPaw's setting.
- After switching languages, notices already on screen keep their language until they appear again.
- The tests detect cut-off and overflowing text, but not text that wraps onto two lines.
